## Known Limitation — Full Training/Evaluation Run Not Executed Live
`train.py`'s actual `FastVisionModel.from_pretrained(...)` / `VLMSFTTrainer.train()` / `evaluate()` call chain was **not** run end-to-end against the real base model this session, for two concrete, honestly-reported reasons rather than a silent gap:

1. **The oMLX server isn't currently running.** `evaluate()`'s live-model comparison (MTR-7) needs it reachable at `localhost:8000` (the same server `ingestion-worker`'s `OPENROUTER_BASE_URL` points at via `host.docker.internal:8000` from inside its container) — checked directly (`lsof -iTCP:8000 -sTCP:LISTEN`, `curl`), nothing is listening right now. This is the user's own separately-managed local model server, outside this project's `docker-compose` stack and outside this session's ability/authority to start.
2. **A real training run is a genuinely heavy operation** — downloading a 4-bit-quantized 26B-parameter model (tens of GB) and running actual LoRA fine-tuning steps — not something to trigger silently as part of an automated verification pass without the user's awareness of the time/bandwidth/compute cost involved.

Everything **structurally verifiable without those two things** has been verified: real package installation, real API-signature matching against the installed code (not the README), a real full curation run against real production data, and a full unit-test pass for every piece of logic that doesn't require the ML runtime itself. What remains is a genuine live smoke-test run of `train.py`, which needs the user to start their oMLX server first.
