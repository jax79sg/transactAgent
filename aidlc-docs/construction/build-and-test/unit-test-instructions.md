# Unit Test Execution

Each unit's tests run independently — no docker-compose stack needs to be running (Python units spin up their own disposable Postgres via testcontainers; the frontend mocks all API calls).

## Prerequisites
- Docker running (required by testcontainers for the 3 Python units)
- Python 3.12+ and Node 20+ on the host (or run inside each unit's own container — see below)

## Database (Unit 1)
```bash
cd database
pip install -e ".[test]"
pytest
```
**Expected**: 12 passed

## API Service (Unit 2)
```bash
cd api-service
pip install -e "../database" -e ".[test]"
pytest
```
**Expected**: 46 passed

## Ingestion Worker Service (Unit 3)
```bash
cd ingestion-worker
pip install -e "../database" -e ".[test]"
pytest
```
**Expected**: 45 passed

## Frontend SPA (Unit 4)
```bash
cd frontend
npm install
npm test        # vitest — unit/component tests + fast-check PBT suite
npm run build   # tsc type-check + production build (also a strong correctness signal)
```
**Expected**: 12 passed, clean build

## Run Everything at Once
```bash
for dir in database api-service ingestion-worker; do
  (cd "$dir" && pip install -e "../database" -e ".[test]" 2>/dev/null; pip install -e ".[test]"; pytest -q)
done
(cd frontend && npm install && npm test)
```

## Total Expected Result
**115 tests passing** across all 4 units (12 + 46 + 45 + 12), plus a clean frontend production build.

## Review Test Results
- **Test Coverage**: Not formally measured with a coverage tool in this project (personal-scale app, Partial PBT mode rather than blanket coverage targets) — instead, every AR-/WR- business rule documented in each unit's `functional-design/business-rules.md` has at least one corresponding positive and negative test case, and the 3 units' worth of Hypothesis/fast-check property tests target every genuinely pure function identified during NFR Requirements.
- **Test Report Location**: stdout from `pytest`/`vitest run`; no separate HTML report generated by default.

## Fix Failing Tests
If a test fails after you've modified code:
1. Re-run the single failing test file for a focused view (e.g., `pytest tests/test_categorization_service.py -v`)
2. Check whether the failure is in application code or a test fixture (several bugs found during original development were test-helper bugs, not app bugs — e.g. a hardcoded hash colliding across multiple rows in one test)
3. Fix and re-run the full suite for that unit before moving on

```bash
cd frontend
cat > /tmp/Dockerfile.test <<'DOCKERFILE'
FROM node:20-alpine
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --no-audit --no-fund
COPY . .
DOCKERFILE
docker build -f /tmp/Dockerfile.test -t ta-frontend-test .
docker run --rm ta-frontend-test sh -c "npx vitest run && npx tsc -b && npx eslint . && npx vite build"
```
