# Logical Components — Unit 4: Frontend SPA

## Component: API Client Module
- **Type**: A single TypeScript module (`apiClient.ts` or similar)
- **Role**: Wraps `fetch`, injects the `Authorization` header from `AuthProvider`'s current token, reads `window.__APP_CONFIG__.apiBaseUrl` as the base URL, centralizes 401-handling (clears session, redirects to `/login`)

## Component: Runtime Config Loader
- **Type**: A `config.js` file generated by the container entrypoint at startup (not build time), loaded before the app bundle
- **Role**: Supplies `apiBaseUrl` to the API Client Module — see NFR Design Pattern above

## Component: Error Boundary
- **Type**: React error boundary component wrapping the routed app
- **Role**: Catches rendering errors, shows a fallback UI

## Component: Query Client (TanStack Query)
- **Type**: A single `QueryClient` instance provided at the app root
- **Role**: Powers all server-state fetching, the ingestion-run polling loop (`refetchInterval`), and category-list caching/invalidation

## No Additional Infrastructure Components

No state-management library beyond TanStack Query (server state) + React's built-in state/context (client state, e.g. `AuthProvider`) — consistent with the "keep it simple" decisions made across all other units.
