**Unit**: Database (Unit 1). **Stories**: US-13.1, US-13.2, US-13.3, US-13.6, US-13.7 (schema layer only; business logic lives in Units 2/3, which own the application-layer rules BR-31, BR-34, BR-35, and BR-36 named below). **Code location**: workspace root, `database/` (existing structure; files are modified in place, never copied). Documentation: `aidlc-docs/construction/database/code/` (markdown only).

## Constraint-enforcement approach (stated up front, since it differs from earlier precedent in one place)

Earlier partial-unique-index rules (BR-10, BR-14, BR-21) were added as raw SQL in a migration, which means the test suite, which builds its schema straight from the models, never exercised them. BR-30's uniqueness (a missing account number counts as a value) can instead be declared **on the model itself** using PostgreSQL's `NULLS NOT DISTINCT` unique constraint (PostgreSQL 15+; this project runs `postgres:16-alpine` in both the stack and the tests). Declared on the model, it is created by `create_all` in tests **and** by the migration, so the tests exercise the real constraint. Step 5 confirms the installed SQLAlchemy supports it before relying on it; if it does not, the fallback is two partial unique indexes in the migration, with the test limitation documented the way earlier migrations did.
